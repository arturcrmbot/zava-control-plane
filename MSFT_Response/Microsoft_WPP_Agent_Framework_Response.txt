2. Executive Summary [Kalai + James]

Microsoft proposes an integrated, multi-layered solution to serve as the core orchestration, runtime, governance, and platform layer for WPP's enterprise agent workforce. Our response is anchored in the following key propositions:

• Unified Agent Framework: Microsoft Agent Framework 1.0 (GA April 2026) is our production-ready, open-source SDK for building, orchestrating, and deploying AI agents and multi-agent workflows. It provides enterprise-grade multi-agent orchestration, multi-provider model support, and cross-runtime interoperability via A2A and MCP.
• Foundry Control Plane: Microsoft Foundry Control Plane provides unified fleet management, observability, compliance enforcement, and security for AI agents across the enterprise. It directly addresses WPP's requirement for a purpose-built fleet management interface supporting the 1:20-50 human-to-agent ratio.
• Full Development Spectrum: From pro-code (Agent Framework for .NET and Python) to low-code (Copilot Studio) to no-code (M365 Copilot Agent Builder), we support every builder persona WPP requires.
• Enterprise Governance: Microsoft Entra Agent ID, Microsoft Defender, and Microsoft Purview deliver identity, security, and compliance governance purpose-built for autonomous agents.
• Deep WPP Ecosystem Integration: WPP's existing M365, Power Platform, Dynamics 365, and Azure investments are natively integrated. No rebuild required.
• Open Standards: Native support for A2A, MCP, and OpenTelemetry ensures interoperability with WPP Open and third-party systems.

4.2 Agent Framework vs Agent Surfaces [Scott + Artur]
Per WPP's requirement in §3.5, we clearly delineate:

The same agent workflow can be invoked from Teams, a Power App, a .NET service, a React front-end, or another agent via A2A, without rebuilding the agent per surface.
4.3 Control Plane Architecture [Scott + Artur] 
Microsoft Foundry Control Plane is our direct answer to WPP's defining architectural principle. It is a unified management interface providing visibility, governance, and control for AI agents, models, and tools across the enterprise.

Key Control Plane capabilities:
• Fleet Dashboard: Real-time status across all active agent workflows, filterable by project, domain, risk level, compliance posture, and cost. Provides a searchable inventory of every AI agent, model deployment, and tool across all projects.
• Exception-Only Filtering: Operators default to seeing only workflows requiring intervention. Autonomous workflows run without cluttering the operator's view.
• Real-Time Observability: End-to-end tracing with OpenTelemetry, including inputs, reasoning steps, tool calls, outputs, latency, and cost per agent run.
• Continuous Evaluation: Automated evaluations on production traffic measuring quality, safety, task adherence, tool call accuracy, and sensitive data exposure.
• Runtime Controls: Configurable intervention points across user input, tool calls, tool responses, and outputs to detect and block PII, prompt injection, task misalignment, and content risks.
• Bulk Operations: Approve, reject, or redirect batches of similar decisions. Policy enforcement across the entire fleet from a single surface.
• Autonomy Configuration: Per-agent and per-workflow autonomy thresholds, adjustable at runtime without redeployment, via the governance policy engine.

This is not a single-agent, single-session surface. It is a purpose-built fleet management interface designed for the 1:20-50 human-to-agent ratio WPP requires.
4.4 Multi-Agent Orchestration [Scott + Artur]
Microsoft Agent Framework 1.0 provides graph-based workflow orchestration as its core capability:
• Workflow Graphs: Sequential, parallel, and conditional routing. Dynamic routing based on intermediate data and business rules.
• Deep Nesting: Sub-workflows within primary workflows for layered logical abstraction.
• Durable Execution: State checkpointing, fault recovery, and resume from last checkpoint after platform restart.
• Human-in-the-Loop: Pause, review, approve, modify, and resume at any point via the Control Plane, not just inline chat.
• Cross-Runtime Interop: A2A and MCP enable agents to collaborate across platforms, including future WPP Open interoperability.

Governance, Security and Compliance [Scott + Artur]
This section addresses §5.2 of the brief. Microsoft provides a comprehensive, integrated governance layer purpose-built for autonomous AI agents.
6.1 Agent Identity and Governance [Scott + Artur]
Microsoft Entra Agent ID (part of Microsoft Agent 365) introduces formal agent identities in Microsoft Entra ID, treating agents as first-class identities in the organisation:
• Agent Identity Blueprint: Governs a class of agent identities for lifecycle operations.
• Agent Registry: Centralized inventory of all agents across Copilot Studio, Azure AI Foundry, and third-party platforms. Framework-agnostic as required.
• Lifecycle Management: From idea to retirement, with responsible person oversight throughout.
• Least-Privilege Access: Scoped permissions via Azure RBAC, integrated with Okta federation via Entra External ID.
• Conditional Access: Apply enterprise Conditional Access, auditing, and lifecycle rules to agent identities.
• Runtime Authorisation: RBAC + ABAC enforcement at the tool-call level with just-in-time approval injection.
6.2 Observability and OpenTelemetry [Scott + Artur]
Foundry Control Plane provides native OpenTelemetry integration:
• End-to-end tracing from inference through tool calls using OpenTelemetry standards
• Every agent run traced: inputs, reasoning steps, tool calls, outputs, latency, and cost
• Continuous evaluation on production traffic with automated quality and safety scoring
• Integration with Azure Monitor, Application Insights, and Azure Log Analytics
• Cost tracking and resource consumption monitoring across the entire AI environment
6.3 Data Protection and Compliance [Scott + Artur]
• Microsoft Purview: DLP enforcement, data classification, and compliance policies extended to all AI agent interactions.
• Microsoft Defender: AI threat protection, jailbreak detection, prompt injection detection, and security incident investigation.
• Compliance: SOC 2, ISO 27001, GDPR compliant with regular third-party audits. Azure's 100+ compliance certifications apply.
• Data Residency: Platform-level enforcement via Azure region policies. Not developer-configured.
• Audit Trails: Immutable audit logs with 7+ years retention, queryable via Azure Log Analytics and Microsoft Sentinel.

10. Code-as-Truth: Auditability and Transparency [Scott + Artur]
This section addresses §6.5 of the brief.

• Agent Definitions: Exportable as structured YAML/JSON configuration files. Includes prompts, model assignments, tool permissions, knowledge source bindings, and autonomy thresholds. All committable to Git.
• Orchestration Harnesses: Workflow graphs represented as declarative configuration. Inspectable, diffable, and reviewable via standard code review processes. The Agent Framework uses declarative agent definitions that can be version-controlled.
• Low-Code Parity: Copilot Studio artefacts serialize to the same configuration format as pro-code artefacts. A workflow built in the visual designer produces a repo-committable artefact identical in structure to one built via SDK.
• Policy-as-Code: Governance rules, autonomy thresholds, approval chains, and data residency constraints are version-controlled with author, timestamp, rationale, and approver per change via Azure Policy and Foundry compliance policies.
• Full Traceability: Every routing decision, model selection, and tool call is fully traceable in OTEL spans and audit logs. Decision rationale, input context, and policy evaluation are logged.

Git-Based Workflow for 50 Agents: A team of 5 developers manages 50 agents across dev, staging, and production using Azure DevOps or GitHub CI/CD pipelines, with environment-specific configuration stored in branches or environment files. Pull request reviews gate all changes. Non-technical auditors inspect agent authorisations, actions, and rationale via the Foundry Control Plane compliance dashboard and audit log queries.
