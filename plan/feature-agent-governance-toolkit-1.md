# Introduction

![Status: Planned](https://img.shields.io/badge/status-Planned-blue)

The substrate today has the right *seams* for governance — a single `call_mcp()` chokepoint in the Functions side ([api/functions/graphs/_common.py](../api/functions/graphs/_common.py)), a single `@traced_tool` decorator on the FastAPI side ([api/server/mcp_tools/_otel.py](../api/server/mcp_tools/_otel.py)), an append-only `actionLedger` on every Workflow ([api/shared/types.py](../api/shared/types.py) §`ActionLedgerEntry`), an append-blob audit logger with version-level immutability ([api/server/services/audit_logger.py](../api/server/services/audit_logger.py)), a delegated-authority matrix with 80+ rules ([data/synthetic/authority/matrix.json](../data/synthetic/authority/matrix.json)), and a persona registry whose `decision_policy` blocks already consult `authority_check` ([api/server/services/persona_responder.py](../api/server/services/persona_responder.py)). What it lacks is a *core*: a deterministic, sub-millisecond policy evaluator that every one of those seams routes through, and a cryptographic spine that turns the ledger from "trust me" into auditor-reproducible evidence.

This plan installs the [Microsoft Agent Governance Toolkit](https://github.com/microsoft/agent-governance-toolkit) (AGT, v3.4.0, MIT, Public Preview) as that core. AGT is **not** a prompt-injection / content-safety layer (Azure AI Content Safety remains the right answer for that, out of scope here). AGT is application-layer policy enforcement: every tool call, resource access, and inter-agent message is evaluated against a declarative policy *before* execution. Deterministic, not probabilistic. Sub-millisecond. Multi-language (we use Python).

The plan is DRY by construction. One `GovernanceKernel` singleton, one **AGT YAML policy bundle** compiled from the existing matrix, one decorator change at each of the two existing chokepoints, one extension to `ActionLedgerEntry`. No domain code touched. No orchestrator code touched. No persona behaviour changed. The result is a substrate where:

- Every `httpx.post()` to an MCP endpoint is denied unless an explicit policy rule allows the `(actor, tool, args, value, business_unit, geography)` tuple — including the 30+ FastAPI tools and the per-graph executors.
- Every authority resolution (today: an HTTP round-trip to `mocks/authority-mcp/` :4108) collapses to one in-process policy evaluation. The Node mock stays in-tree as the engagement-POC swap-in seam (Foundry-IQ contract preservation) but is no longer started by `boot-demo.sh`; spin it up only for the explicit parity test.
- Every ledger entry carries `prev_hash`, `entry_hash`, `decision_id`, `policy_version`, `actor_jws`. The blob is now a hash chain. A single `agt verify --evidence <blob-url>` validates the entire chain end-to-end against the policy bundle that was live at each timestamp.
- The autonomous demo runs **enforce-mode by default** (`AGT_ENFORCE=1` in the canonical demo profile); a deny becomes a visible workflow exception via the existing exception narrative path — auditable demo material.
- Every machine agent (`finance-agent`, `escalation-advisor`, `compliance-classifier`, etc.) has an Ed25519 identity persisted in the registry, with declared `allowed_tools` and `max_value_gbp`. Capability creep ("which tools can finance-agent actually call?") becomes a one-line registry lookup.
- Irreversible tool calls (e.g. `concur.submit_decision`, `workday_hr.write_*`, `graph.send_mail`) are denied unless an explicit ALLOW with `priority ≥ ENFORCE_FLOOR` matches; the only thing producing such an ALLOW is a closed HITL gate.
- The Finance Controller surface from [poc1-brief.md §3](../docs/poc1-brief.md#sec-3) gains "pause this agent" / "block this tool fleet-wide for 30 min" controls — zero-redeploy containment via the AGT kill switch table.
- CI fails the PR on tool poisoning in any `mocks/*-mcp/`, dead AGT YAML rules, conflicting policies, or unregistered agents discovered by `agt discover`.

Each phase ships independently green. Phase 2 introduces the kernel in **log-only mode** (every decision recorded, none enforced) so the existing 90/90 test suite keeps passing while we tune. Phase 6 flips the switch to enforce. Phases 1–8 are atomic and ship incrementally with no acceptance-criteria regression against POC1, POC2, or the eight fleet-* domains. **Scope is POC1 + POC2 only**; POC3 (the creative-campaign worktree at `wpp-control-plane-poc3-ai-agency`) is explicitly out of scope, and Phase 8 produces a POC3-portable handoff document so POC3 can adopt the same governance core as a separate plan without re-deriving the design.

## 1. Requirements & Constraints

- **REQ-001**: Every MCP tool call from any code path inside `api/` MUST pass through `GovernanceKernel.evaluate_tool_call(...)` before the network hop. The two enforcement points are `call_mcp` in [api/functions/graphs/_common.py](../api/functions/graphs/_common.py) and the `@traced_tool` decorator in [api/server/mcp_tools/_otel.py](../api/server/mcp_tools/_otel.py). No third enforcement point may exist; any new MCP integration MUST route through one of these two.
- **REQ-002**: Every persona's `_sandbox_authority_check` invocation in [api/server/services/persona_responder.py](../api/server/services/persona_responder.py) MUST resolve through the in-process kernel first. The HTTP round-trip to `mocks/authority-mcp/` (:4108) is retained as a fallback when env var `AUTHORITY_MCP_URL` is set, preserving the engagement-POC Foundry-IQ swap-in seam guaranteed by [feature-authority-and-personae-1.md](feature-authority-and-personae-1.md) GUD-001. The Node mock stays in-tree but is removed from the default `boot-demo.sh` startup; it is started only when `AUTHORITY_MCP_LIVE=1` is set or when an engagement-POC swap-in points at it.
- **REQ-003**: The 80-rule matrix at [data/synthetic/authority/matrix.json](../data/synthetic/authority/matrix.json) MUST compile to a deterministic **AGT YAML policy bundle** at process boot, consumable by `agent_os.policies.PolicyDocument`. Bundle is regenerated every boot from the canonical inputs (no committed `.yaml` artefact during this plan; see CON-005). Compilation failure halts boot with a clear error pointing at the offending rule_id.
- **REQ-004**: `ActionLedgerEntry` ([api/shared/types.py](../api/shared/types.py) line 104) MUST gain four optional fields — `prev_hash: str | None`, `entry_hash: str | None`, `actor_jws: str | None`, `decision_id: str | None` — without breaking any of the 17 existing test sites that construct `ActionLedgerEntry` directly. Optional means default `None`; back-compat is non-negotiable.
- **REQ-005**: Every machine agent that calls MCP tools MUST be enumerated in a new registry `api/shared/agents.py` (sister to [api/shared/personas.py](../api/shared/personas.py) and [api/shared/domains.py](../api/shared/domains.py)). Each entry declares `agent_id`, `allowed_tools: list[str]`, `max_value_gbp: float | None`, `reversible_only: bool`, `scope_function`. The registry is the single source of truth; no agent_id may appear in any ledger entry that isn't in the registry (validated in CI).
- **REQ-006**: Each registered agent MUST have an Ed25519 keypair. In dev (`AGT_DEV_KEYS=1` or default), keypairs are generated at boot and persisted to `azurite-data/agt-keys/` (gitignored). In production, public keys are committed to `data/governance/agent-pubkeys/<agent_id>.pub`; private keys are loaded from Azure Key Vault via `DefaultAzureCredential`, mirroring the auth pattern in [api/server/services/audit_logger.py](../api/server/services/audit_logger.py).
- **REQ-007**: Each MCP tool used by the substrate MUST have a manifest entry in `data/policies/tools.yaml` declaring `id`, `reversible: bool`, `requires_capability: str | null`, `requires_authority: bool`, `value_field: str | null` (the JSON path inside `args` to extract the GBP value, e.g. `claim.amount_gbp`). Tool calls without a manifest entry fail closed in enforce mode, log a warning in log-only mode.
- **REQ-008**: The kernel MUST run in two modes selectable per-call by policy: `log_only` (default through Phase 5) records the decision into the ledger but does not raise; `enforce` (Phase 6 onwards, controlled by `AGT_ENFORCE=1`) raises a `GovernanceDenied` exception that bubbles to the caller and aborts the workflow phase. The mode is recorded on every ledger entry as `enforcement_mode` for forensic clarity.
- **REQ-009**: A new endpoint `POST /api/governance/kill {actor, tool, ttl_seconds, reason}` MUST flip a kill-switch flag in the `StateStore` ([api/server/services/state_store.py](../api/server/services/state_store.py)). The kernel consults the flag at every evaluation. Toggling is sub-second; no redeploy. Endpoint is operator-authenticated (matches the existing operator-auth pattern on `/api/personas` and `/api/authority/matrix`).
- **REQ-010**: A new endpoint `GET /api/governance/verify/{workflow_id}` MUST run `agt verify` against the workflow's append blob and return `{chain_intact: bool, signatures_valid: bool, decisions_resolvable: bool, broken_at: str | null}`. The Control Plane WorkflowDetail page renders the result as a coloured "Evidence" chip alongside the existing "Authority" chip from [feature-authority-and-personae-1.md](feature-authority-and-personae-1.md) TASK-035.
- **REQ-011**: A nightly CI job MUST run `agt mcp-scan mocks/`, `agt lint-policy data/policies/`, `agt verify --strict`, and `agt discover --root .`. Any of the four failing fails the build. The four reports are aggregated into a single JSON artefact `agt-evidence.json` published as a CI artifact and consumed by the blueprint microsite as the "OWASP Agentic Top 10" card.
- **REQ-012**: The autonomous demo loop (`./scripts/profile-autonomous.sh` + `SIMULATOR_RAMP_ENABLED=1`) and the canonical 90/90 test suite MUST remain green after every phase. Each phase MUST ship independently with a single PR that flips no behavioural switch (default-deny only takes effect in Phase 6).
- **SEC-001**: AGT YAML policy bundles are deterministic — the same matrix.json + tools.yaml MUST produce byte-identical YAML source (sorted keys, fixed key order on rules, no timestamps). Hash of the bundle is recorded on every decision_id, so any policy drift is detectable post-hoc.
- **SEC-002**: The kernel MUST NOT swallow exceptions. A `GovernanceDenied` is a first-class control-flow signal in enforce mode; a kernel failure (e.g. policy compilation error at runtime) is a fail-closed deny, never a silent allow. There is no env var that turns the kernel off — to disable governance you uninstall AGT and edit the chokepoints.
- **SEC-003**: Private signing keys MUST NEVER be logged, included in audit blobs, or returned over any HTTP endpoint. `agt verify` operates on public keys only. Every audit entry's `actor_jws` field is verifiable with the corresponding pubkey under `data/governance/agent-pubkeys/`.
- **SEC-004**: `tools.yaml` MUST mark every `*.write_*`, `*.submit_*`, `*.send_*`, `*.cancel_*`, `*.delete_*` entry as `reversible: false`. The CI ring (Phase 8) greps the manifest for any reversible-true tool whose name matches the destructive pattern and fails the build.
- **SEC-005**: No org-specific identifiers, agency names, or proprietary process language in any new file. Reviewer must `grep -riE 'wpp|vml|ogilvy|wunderman|groupm|hogarth|kantar' api/server/services/governance/ api/shared/agents.py data/policies/ data/governance/` and find zero hits.
- **CON-000**: **Scope target is demo-credibility for the WPP review**, not full production. Local Ed25519 keys are acceptable; Key Vault wiring is documented but deferred to engagement-POC. CI gates fail PRs from Phase 8 onwards but a documented `AGT_ENFORCE=0` env-var escape hatch exists for emergency demo recovery (and only that profile path).
- **CON-001**: AGT runs in-process with the FastAPI app and the Functions worker. Same trust boundary as the rest of the Python code (this is AGT's documented Security Boundary; OS-level isolation is a deployment story handled by the existing Container Apps split, not by this plan).
- **CON-002**: AGT v3.4.0 is in Public Preview. We hard-depend on it (`agent-governance-toolkit[full]==3.4.*`); breaking changes are possible before GA but we keep the integration surface narrow (`api/server/services/governance/__init__.py` is the *only* import site for `agent_os.*`, `agentmesh.*`, etc.). Upgrades are then a single-file diff. If Phase 1 discovers the AGT surface differs materially from the README, we halt and revisit — we do not write a shim layer.
- **CON-003**: No per-domain code is modified. The eight fleet-* orchestrators ([api/functions/workflows/fleet_*.py](../api/functions/workflows)), the per-phase graphs ([api/functions/graphs/](../api/functions/graphs)), the persona SKILL.md files ([api/server/personae/](../api/server/personae)), and the agent skills ([api/server/skills/](../api/server/skills)) are out of scope. Governance is a pure infrastructure concern.
- **CON-004**: No frontend changes through Phase 6. Phase 7 introduces one new panel on the existing WorkflowDetail page and three new buttons on the existing Fleet rail. No new top-level navigation.
- **CON-005**: The compiled AGT YAML bundle is **not** committed during this plan — it's regenerated at boot from `matrix.json` + `tools.yaml`. A future plan may flip to a committed bundle for reproducibility audits; today the inputs are the source of truth.
- **CON-006**: Local-first. AGT requires no Azure resource provisioning beyond what already exists (storage account for audit blobs is unchanged). Key Vault access is the only new prod-time permission; in dev (the demo path), generated keys land in `azurite-data/agt-keys/`.
- **CON-007**: **POC1 + POC2 only.** POC3 (`wpp-control-plane-poc3-ai-agency` worktree) is explicitly out of scope. Phase 8 (TASK-064a, new) produces a POC3-portable handoff document — `docs/governance-poc3-adoption-guide.md` — capturing the design, the wiring points (which are the same `_common.py` + `_otel.py` chokepoints), the registry-extension procedure for creative-campaign agents, and a per-phase task list mirroring this plan. POC3 adopts as a separate plan from that doc.
- **GUD-001**: `GovernanceKernel` is a frozen dataclass-style singleton constructed at app startup, mirroring the construction pattern of `AuditLogger` in [api/server/services/audit_logger.py](../api/server/services/audit_logger.py). One module-level instance, accessed via `governance.kernel()` getter. No DI framework.
- **GUD-002**: AGT YAML policies are emitted by a pure compiler `policy_compiler.py` whose only inputs are `matrix.json` + `tools.yaml` + `agents.py`. The compiler is unit-tested with golden-file fixtures so any change to matrix shape causes a visible diff in the generated YAML source. (We chose AGT YAML over Cedar/Rego because the matrix shape is already YAML/JSON-shaped and round-trips cleanly; CI diffs read like data, not policy DSL.)
- **GUD-003**: All new code follows the Pydantic-models-and-dataclasses convention already established in [api/shared/types.py](../api/shared/types.py) and [api/shared/personas.py](../api/shared/personas.py). No new ORM, no new DI container, no new logging library.
- **GUD-004**: Tests live alongside the code under `tests/api/server/services/governance/` and `tests/api/shared/test_agents.py`. The CI matrix already covers these paths. No new top-level test directory.
- **PAT-001**: Single chokepoint per side: `call_mcp` (Functions side) and `@traced_tool` (FastAPI side). Both call into the same kernel; the kernel doesn't care which side called it. DRY by construction.
- **PAT-002**: The kernel is reentrant and thread-safe. Decisions are pure functions of `(policy_bundle_hash, request_tuple)`; the in-memory cache is keyed by that pair with a 60s TTL.
- **PAT-003**: The audit chain is per-workflow (one chain per blob), not global. This matches the existing one-blob-per-workflow layout in `audit_logger.py` and makes parallel writes safe (no global lock).
- **PAT-004**: Receipts are JWS Compact Serialization (RFC 7515), Ed25519 (`EdDSA`). Verification is a pure function of `(public_key, jws, payload_hash)`; no network.

## 3. Alternatives

- **ALT-001**: Bespoke policy engine. Rejected. We've already drafted ~80 rules in `matrix.json`; building our own evaluator means owning policy semantics, an audit format, a CLI, and OWASP mapping. AGT gives all of this with one dependency.
- **ALT-002**: Azure AI Content Safety only. Rejected as a substitute (it's a complement). Content Safety operates on LLM input/output strings; it does not see tool-call args, MCP tool definitions, or actionLedger writes. The threats this plan addresses (capability creep, ledger tampering, irreversible-call hallucination, shadow agents) are invisible to Content Safety.
- **ALT-003**: OPA / Open Policy Agent as a sidecar. Rejected for now — adds a network hop per tool call (50–100µs vs the kernel's 10µs in-process), and we'd still need to author the audit chain, identity, kill switch, MCP scanner, and CLI ourselves. AGT bundles all of these.
- **ALT-003a**: Cedar instead of AGT YAML. Rejected per user decision: matrix.json is already YAML/JSON-shaped; round-tripping through YAML keeps CI diffs readable as data. Cedar's `permit(principal == ..., action == ..., resource)` syntax adds a translation layer between the matrix and the policy without buying us anything for our use case (we don't need ABAC composition over hierarchical resources).
- **ALT-004**: Microsoft 365 / Entra Agent 365 governance plane. Rejected at this layer — Agent 365 is the *admin/observe/govern* surface for *deployed agents*; this plan is the in-process *enforcement* surface inside one substrate. They are complementary and orthogonal; Agent 365 wiring is a deployment-time question for the engagement-POC, not a code question for this repo.
- **ALT-005**: Defer to POC3. Rejected. The "30–50 concurrent expense workflows" claim in [poc1-brief.md §3](../docs/poc1-brief.md#sec-3) and the "deterministic, audited" language in the Capability Assessment Criteria are POC1/POC2 acceptance criteria. Governance has to ship before the WPP review, not after. POC3 adopts via the handoff guide (CON-007, TASK-064a).

## 7. Risks & Assumptions

- **RISK-001**: AGT v3.4 is Public Preview (CON-002). We hard-depend (no shim layer per user decision). Mitigation: pin to `3.4.*`, narrow import surface to `api/server/services/governance/__init__.py`, **TASK-008 includes an explicit AGT-surface probe** — if `from agent_os.policies import PolicyEvaluator, PolicyDocument, PolicyRule, PolicyCondition, PolicyAction, PolicyOperator, PolicyDefaults` fails, halt Phase 2 and revisit.
- **RISK-002**: AGT YAML evaluator semantics may not 1:1 match the existing `mocks/authority-mcp/resolver.js` first-match-wins walk (AGT uses `priority` integers, not insertion order). Mitigation: `policy_compiler` assigns descending integer priorities matching insertion order; TASK-021 parity test covers all 8 canonical resolutions; tighten the compiler until they agree byte-for-byte before flipping any caller.
- **RISK-003**: Phase 6 enforce-mode flip exposes hidden coupling — agents that have been calling tools they're not "supposed" to. Mitigation: the iteration loop in TASK-049 fixes the registry at the source rather than weakening the kernel. Worst case adds a few entries to `agents.py.allowed_tools` and re-runs.
- **RISK-004**: JWS signing on every ledger write adds latency. Ed25519 sign is ~50µs; the current ledger writes are already disk/network bound (10s of ms). Mitigation: measure once after Phase 5; if the budget is tight, batch-sign per-workflow at flush time rather than per-entry. Either way the signature ends up on the entry.
- **RISK-005**: Hash chain serialisation differences between Python's `json.dumps` and the verifier's reader can cause false-positive "broken chain". Mitigation: canonical JSON via `canonicaljson` package, or bytewise-identical re-serialisation through the same code path. Test TASK-032 exercises this.
- **RISK-006**: Key Vault permissions in production. Mitigation: dev path is fully local (REQ-006); the Key Vault wiring is a deploy-time concern documented in TASK-044's runbook, deferred to the engagement-POC swap.
- **ASSUMPTION-001**: The 80+ rules in `matrix.json` are correct and deterministic enough to compile. They've been validated in [feature-authority-and-personae-1.md](feature-authority-and-personae-1.md) Phase 1, so this is low-risk.
- **ASSUMPTION-002**: The agent_label values currently flowing through `agent_reasoning` are stable enough to enumerate as a registry. TASK-034 audits this; if there's drift, it's contained to one file (`api/shared/agents.py`).
- **ASSUMPTION-003**: AGT's `PolicyEvaluator` supports the rule shape we need (per-tuple field matching with priority-ordered first-match). The README example confirms YAML / OPA-Rego / Cedar are all supported; we use the YAML path. Verified against AGT v3.4 README example which shows `PolicyEvaluator(policies=[PolicyDocument(rules=[PolicyRule(condition=..., action=PolicyAction.DENY, priority=100)])])`.
- **ASSUMPTION-004**: The blueprint microsite deploy already publishes static JSON artefacts (per [docs/blueprint-microsite-contributor-guide.md](../docs/blueprint-microsite-contributor-guide.md)). TASK-059 reuses that channel for `agt-evidence.json`.
