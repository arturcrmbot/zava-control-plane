# Introduction

![Status: Not Started](https://img.shields.io/badge/status-Not%20Started-lightgrey)

Phase 4 is the final movement of the Agentic Org Blueprint v3 rollout. Phases 1–3 give us the substrate this plan plugs into: Phase 1's Kuzu-backed `EntityGraph` with `Decision` nodes and the projection registry; Phase 2's `compose-domain v4` skill (whose "domains" include the per-function FMs themselves); Phase 3's `FunctionFleetManager`, `AmbientAgent` (with `CadenceTrigger` declared but not yet fired), the five MCP tools (incl. a `query_kpi` stub), and per-function SSE topics.

This plan turns those primitives into a living org-clone. Cadences fire ambient agents on cron. KPIs are real time-series, published by every function FM and aggregated by the CEO-FM. Personae query closed `Decision` nodes for precedent before deciding. The first three meta-workflows (`hire-to-productive`, `vendor-risk-to-pay`, `lead-to-cash`) are graduated as ordinary domains whose orchestrators happen to call sub-orchestrators against existing fleet domains. The CEO-FM is itself graduated as `function: ceo` via `compose-domain v4` — same shape as any other function FM, with two strategic domains (`fy-close`, `board-prep`) that no function FM owns. A new `/admin/org-clone` blueprint page is the single pane of glass that shows it all running.

Phase 4 also resolves the five open questions left in blueprint §12 — see the decisions block in §1 below.

## 1. Requirements & Constraints

**Open-question decisions (blueprint §12 — resolved here):**

- **DEC-OQ1 — Decision-as-precedent retrieval shape:** **tool call.** Personae do not inline a Cypher fetch. The persona responder gains a registered `query_precedents(persona_role, entity_id, limit)` tool, mirroring how Phase 3's `query_economics` is wired. This keeps the responder pure and consistent with the FM context strategy from blueprint §10 decision #9 (hybrid: static identity + dynamic state via MCP tools). Referenced by TASK-014, TASK-015.
- **DEC-OQ2 — CEO-FM operator surface:** **same shape as a function FM, distinct page.** A new `/ceo` operator surface is added; a distinct `/functions/ceo` panel is added to the blueprint. Reuses the per-function FM shape from Phase 3 with one additional MCP tool `query_function_fm(function, prompt)` so CEO-FM can delegate to a specific function FM. Referenced by TASK-026, TASK-027, TASK-029.
- **DEC-OQ3 — KPI schema versioning:** **schema-versioned per snapshot, readers tolerate missing keys.** Each row in `data/portal/kpis.sqlite` carries a `schema_version` int. Each function FM declares a `kpi_schema_version` constant in `FUNCTIONS`. CEO-FM aggregation tolerates the union of versions seen and projects missing keys as `null`. Referenced by TASK-008, TASK-010, TASK-029.
- **DEC-OQ4 — Ambient-agent `reasoning_skill` economics:** **route through the existing `economics.py` cost ledger** with a new `cost_kind="ambient_reasoning"` and `actor=f"ambient.{agent_name}"`. Surfaced in the per-function FM panel via the existing economics MCP tool. Referenced by TASK-035.
- **DEC-OQ5 — Meta-workflow visualisation:** **`/api/workflows/{id}/tree`** returns the sub-orchestrator tree shaped from the `Workflow → Workflow` self-relation in the entity graph. The blueprint workflow detail page gains a tree-shaped widget. The existing flat `/api/workflows` endpoint is unchanged. Referenced by TASK-031, TASK-032.

**Functional & structural requirements:**

- **REQ-001:** Cadence YAML loader at boot reads every file under `data/governance/cadences/*.yaml`, parses the `schedule` cron expression (via `croniter`), and registers one asyncio task per cadence on `AppState`. Loader fails loudly on malformed YAML or an unknown `fires_ambient_agent`.
- **REQ-002:** On every cadence tick, the loop dispatches to the matching `AmbientAgent` (registered in Phase 3) by name, passing the cadence name as trigger context. The loop emits one `cadence.tick` audit event per dispatch.
- **REQ-003:** Three cadences ship in this phase: `morning-sweep` (weekdays 09:00), `period-close` (1st of month 06:00), `quarterly-okr` (1st day of Jan/Apr/Jul/Oct 08:00). Each names an existing or newly-added ambient agent.
- **REQ-004:** KPI store at `data/portal/kpis.sqlite` exposes one table `kpi_snapshot(function TEXT, metric TEXT, period TEXT, value REAL, schema_version INT, captured_at TEXT)` with a composite index on `(function, metric, period)`. `FunctionFleetManager.publish_kpi(metric, value, period)` writes one row, stamped with the FM's declared `kpi_schema_version`. Phase 3's `query_kpi` stub is rerouted to read from this store.
- **REQ-005:** `precedent_query` Cypher per `(workflow_type, phase)` is generated by `compose-domain v4` and lands at `api/server/services/precedent_queries/<workflow_type>_<phase>.cypher`. A new `query_precedents` tool is registered with the persona responder using the existing tool-registration pattern (mirror `query_economics`). Personae call the tool from their `decision_code` block.
- **REQ-006:** CEO-FM is graduated as `function: ceo` via `compose-domain v4`. A `FUNCTIONS["ceo"]` entry is added with `kpi_schema_version=1`, `domains=["fy-close", "board-prep"]`, and `extra_mcp_tools=["query_function_fm"]`. The CEO-FM runtime is instantiated like any other `FunctionFleetManager`.
- **REQ-007:** First three meta-workflows are graduated via `compose-domain v4` with the new sub-orchestrator phase generator: `hire-to-productive` (function: `hr`), `vendor-risk-to-pay` (function: `finance`), `lead-to-cash` (function: `revenue`). Function-name keys must match the `FUNCTIONS` registry shipped in Phase 3 TASK-001 (`hr`/`finance`/`revenue`, **not** `chro`/`cfo`) — the C-suite shorthand is reserved for prose, not for the brief's `function:` field. Each lands as `api/functions/workflows/<meta>.py` plus its `_activities.py` sibling.
- **REQ-008:** Strategic CEO-FM domains `fy-close` and `board-prep` are graduated via `compose-domain v4` with `function: ceo`. They land at `api/functions/workflows/fy_close.py` and `api/functions/workflows/board_prep.py`.
- **REQ-009:** `/admin/org-clone` page in the existing blueprint microsite renders: entity counts by kind (from `/api/entities/_stats`), active meta-workflow tree (from `/api/workflows/{id}/tree`), ambient agents with last-trigger + state (from `/api/functions/{name}/ambient`), function FMs with last-cycle KPI snapshot (from `/api/functions`), and the cadence schedule (from a new `/api/cadences`).
- **REQ-010:** End-to-end smoke = the org-clone runs unattended overnight on the autonomous profile with cadences firing, FMs alerting, meta-workflows firing across functions, and the CEO-FM producing a daily brief from real data the substrate generated.

**Security & governance:**

- **SEC-001:** Every cadence tick is a `cadence.tick` audit event carrying `{cadence_name, scheduled_for, fired_at, ambient_agent}`.
- **SEC-002:** Every meta-workflow sub-spawn is a `workflow.sub_spawned` audit event carrying `{parent_workflow_id, child_workflow_id, child_workflow_type}`. Emitted by an instrumentation wrapper around `context.call_sub_orchestrator` injected by the compose-v4 sub-orchestrator codegen.
- **SEC-003:** Every closed `Decision` write is a `decision.recorded` audit event carrying the ULID `decision_id` (locked decision §10 #4) so the audit ledger and the graph node share a key.
- **SEC-004:** Every ambient-agent dispatch (already `ambient.decided` from Phase 3) is extended to carry `trigger_kind` ∈ `{bus, cypher, cadence}` and, for cadence triggers, the `cadence_name`.
- **SEC-005:** Kill switches gain wildcard reach: `kill --actor=cadence.* --tool=*` pauses every cadence-fired actor; `kill --actor=ambient.* --tool=*` pauses every ambient agent fleet-wide.
- **SEC-006:** `precedent_query` Cypher files are read-only by construction — the loader rejects any file containing `CREATE`, `MERGE`, `DELETE`, `SET`, `REMOVE`, `DROP`.

**Constraints:**

- **CON-001:** **No new orchestrator engine.** Meta-workflows use Durable Functions' native `context.call_sub_orchestrator` + `context.task_all`. No `ChoreographyEngine` (blueprint §11).
- **CON-002:** **No `CadenceRunner` class.** Cadences are a YAML loader + an asyncio loop owned by `AppState`. Total <100 LoC across loader + loop (blueprint §11, §2 Plane 4).
- **CON-003:** **No new agent runtime.** GHCP SDK + MAF stays. CEO-FM is an instance of the same `FunctionFleetManager` class shipped in Phase 3, parameterised differently (blueprint §11).
- **CON-004:** **CEO-FM graduates through compose-v4 like any other domain.** Do not hand-author it. The `function: ceo` brief lives at `docs/superpowers/specs/ceo-fm.yaml` and is processed by the same skill that processes every other function (blueprint §2 Plane 4).
- **CON-005:** **No payload migration.** POC1/POC2 stay on `function="legacy"` (locked decision §10 #8). They are not first-class citizens of the meta-workflow tree.
- **CON-006:** **Cadence YAML schema is intentionally minimal:** `name`, `schedule`, `fires_ambient_agent`. Anything richer belongs on the `AmbientAgent` itself.
- **CON-007:** **Precedent queries are pure Cypher.** No Python in the `.cypher` files. The tool layer parameter-binds; the file is the query.

**Guidelines & patterns:**

- **GUD-001:** Cadence loop reuses `croniter` (MIT-licensed, single small dep). Verify it is not already in `pyproject.toml` before adding; if added, pin via Poetry/uv as appropriate to the repo's existing dep convention.
- **GUD-002:** KPI store is a thin sqlite wrapper sibling to `data/portal/magic_links.sqlite` (same pattern as `MagicLinkStore`). One module: `api/server/services/kpi_store.py`.
- **GUD-003:** CEO-FM skill text reuses the existing `api/server/skills/fleet-manager/SKILL.md` template, parameterised at session start with `function: ceo` and the CEO's `extra_mcp_tools` block — same templating mechanism as Phase 3 introduced for per-function FMs.
- **GUD-004:** The meta-workflow phase generator extends compose-v4's existing orchestrator codegen — it does not duplicate it. The brief schema gains one new `kind` discriminator value; the codegen branches on it.
- **GUD-005:** The `Workflow → Workflow` self-relation in the entity graph (created by Phase 1's projection registry, written by the `workflow.sub_spawned` audit instrumentation) is the **one** source of truth for the tree endpoint. Do not parse Durable runtime state.

- **PAT-001:** Cadence YAML at `data/governance/cadences/<name>.yaml` — one file per cadence. Filename matches `name`.
- **PAT-002:** KPI publish API on `FunctionFleetManager`: `publish_kpi(metric: str, value: float, period: str) -> None`. Period is ISO ("2026-05" for monthly, "2026-Q2" for quarterly, "2026-05-08" for daily).
- **PAT-003:** Precedent tool registered via the persona responder's existing tool-registration pattern (mirror `query_economics`). Tool name: `query_precedents`. Args: `persona_role`, `entity_id`, `limit`.
- **PAT-004:** Meta-workflow brief includes a `phases:` block whose entries can be `kind: agent`, `kind: hitl` (existing) or `kind: sub_orchestrator` (new). Sub-orchestrator entries declare `target_workflow_type` + `payload_from` (a Cypher snippet that fetches the input dict from the entity graph).
