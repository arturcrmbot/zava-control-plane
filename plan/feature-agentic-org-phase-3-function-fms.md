Phase 3 builds **Plane 2** of the Agentic Org Blueprint
([docs/agentic-org-blueprint.md §2](../docs/agentic-org-blueprint.md), §5,
§9 Phase 3, locked decisions #2/#5/#7/#8/#9). It depends on Phase 1
([feature-agentic-org-phase-1-entity-graph.md](feature-agentic-org-phase-1-entity-graph.md))
which delivered KuzuDB + the `EntityGraph` service, and on Phase 2
([feature-agentic-org-phase-2-compose-v4.md](feature-agentic-org-phase-2-compose-v4.md))
whose `author-function-membership` and `author-ambient-trigger`
sub-skills target the schemas this phase introduces.

The output is the **persistent agentic department**: every registered
function (finance, hr, revenue, ops, legal, marketing, tech, data,
customer-success, plus a `legacy` placeholder for POC1/POC2) has its own
`FunctionFleetManager` long-running session whose static identity (KPIs,
owned domains, persona hierarchy, ambient watchers) is **templated from
`FUNCTIONS`** at session start, and whose dynamic state comes from five
in-process MCP tools that wrap the entity graph and existing
fleet-manager state. Each FM is also wired to a list of
`AmbientAgent` declarations that subscribe to the `EventBus`
(`BusTrigger`), sweep Cypher patterns on a per-agent tempo
(`CypherTrigger`), or expose a hook for the Phase 4 cadence loop
(`CadenceTrigger`).

This phase deliberately ships **the primitive, not the catalogue**. The
meta-workflows (`hire-to-productive`, `vendor-risk-to-pay`,
`lead-to-cash`) and the C-suite layer arrive in Phase 4. Phase 3
proves the substrate by booting 5+ function FMs and lighting at least
one ambient-spawned workflow per FM in the autonomous-profile demo.

## 1. Requirements & Constraints

- **REQ-001**: `api/shared/functions.py` declares a `FUNCTIONS: dict[str, Function]` registry — one entry per function (`finance`, `hr`, `revenue`, `ops`, `legal`, `marketing`, `tech`, `data`, `customer-success`, plus `legacy`) — each carrying `name`, `display`, `operator_surface`, `owns_domains: tuple[str, ...]`, `ambient_agents: tuple[str, ...]`, `kpis: tuple[str, ...]`, `persona_hierarchy: PersonaTree`. Mirrors the dataclass + module-level dict shape of `api/shared/domains.py`.
- **REQ-002**: `api/shared/domains.py` widens the `Domain` dataclass with `function: str | None = None` (mutable default via `field(default=None)` if needed — switch from `frozen=True` to `frozen=False` only on the `function` field by reconstructing via `dataclasses.replace`, or hold the back-ref in a parallel `_DOMAIN_FUNCTION: dict[str, str]` indirection if frozenness must be preserved). At import time, call `_wire_function_back_refs()` which iterates `FUNCTIONS`, resolves every `owns_domains` entry against `DOMAINS`, and **fails loudly** on (a) unknown domain in any `owns_domains`, (b) any `DOMAINS` entry left unclaimed.
- **REQ-003**: POC1 (`expense-claim`) and POC2 (`hiring`) are assigned to `FUNCTIONS["legacy"]` so the boot validator passes; they remain invisible to every non-legacy `FunctionFleetManager` (locked decision #8).
- **REQ-004**: `AmbientAgent` is a `dataclass(frozen=True)` carrying `name: str`, `function: str`, `triggers: tuple[Trigger, ...]`, `reasoning_skill: str | None`, `spawnable_workflow_types: tuple[str, ...]`. `Trigger` is a discriminated union over `BusTrigger(kind="bus", event_type, filter)`, `CypherTrigger(kind="cypher", pattern, sweep_seconds=3600)`, `CadenceTrigger(kind="cadence", cron)` (locked decision #5).
- **REQ-005**: `api/server/services/ambient_agents/<function>.py` modules declare module-level `AmbientAgent` instances (mirror of the `DOMAINS` declaration pattern). `api/server/services/ambient_agents/__init__.py` discovers all declared agents at import time and exposes `AMBIENT_AGENTS: dict[str, AmbientAgent]` keyed by `name`. Phase 2's `author-ambient-trigger` sub-skill writes into these files; Phase 3 ships the empty modules ready to receive entries plus the three concrete agents in REQ-009.
- **REQ-006**: `FunctionFleetManager` is instantiated **once per non-legacy function** in `AppState`. Its session is created the same way `FleetManagerService` creates today (long-running GHCP SDK session via `CopilotClient`), with its skill text built by templating `api/server/skills/fleet-manager/SKILL.md` against the function's `FUNCTIONS[name]` entry (KPIs, domains owned, persona hierarchy, ambient watchers). The substrate's existing `FleetManagerService` continues to run as the **fleet-wide supervisor** (POC1/POC2/legacy + cross-cutting); per-function FMs supplement it.
- **REQ-007**: Five new in-process MCP tools land under `api/server/mcp_tools/`: `query_fleet_state.py`, `query_kpi.py`, `query_recent_decisions.py`, `query_entity.py`, `find_entities.py`. Each exposes a `make_*_tool(...)` factory matching the `make_query_fleet_tool` pattern in `api/server/mcp_tools/__init__.py`. They are registered with every per-function FM session via a new `build_function_fm_tools(store, audit, graph, function_name)` factory in `api/server/mcp_tools/__init__.py`.
- **REQ-008**: `api/server/services/sse_hub.py` widens `Topic` with one entry per function (`fleet-manager.finance`, `fleet-manager.hr`, …, `fleet-manager.customer-success`). The per-function FM constructor calls `hub.broadcast(f"fleet-manager.{function}", ...)` from its `_on_live` hook (mirror of `main.py`'s existing `_on_live → broadcast("fleet-manager", ...)`).
- **REQ-009**: First three concrete `AmbientAgent` declarations land in this phase: **BudgetVarianceWatcher** (CFO-FM, `CypherTrigger` hourly sweep over `Money` nodes with variance > 10%, spawns `variance-investigation`), **VendorRiskWatcher** (CFO-FM, `CypherTrigger` daily sweep over `Organisation` nodes with `risk_band="high"` linked to in-flight `ap-invoice` workflows, spawns `vendor-risk-review`), **AccessAnomalyWatcher** (CTO-FM bus, `BusTrigger` on `it-access-request.completed` with filter on broad-scope grant, spawns `access-review`).
- **REQ-010**: New `/api/functions` read endpoint and a blueprint observatory `/functions` microsite page consume the registry (functions listed with their KPIs, owned domains, ambient agents, last per-FM heartbeat from the SSE topic).
- **REQ-011**: Smoke-test acceptance: substrate has **5+ function FMs running**, each watching its function's slice of the graph, each spawning **≥1 ambient workflow** in the autonomous-profile demo within 10 minutes of boot.
- **SEC-001**: Every ambient-agent decision emits an `ambient.decided` audit event via the existing `AuditLogger` (hash-chained), carrying `{ambient_agent: str, function: str, trigger_kind: "bus"|"cypher"|"cadence", trigger_payload: dict, spawn_outcome: {"spawned": bool, "workflow_type": str|None, "workflow_id": str|None, "skipped_reason": str|None}}`.
- **SEC-002**: Kill switches gain wildcard reach — `kill --actor=ambient.* --tool=*` pauses **all** ambient agents fleet-wide. The matcher in `api/server/services/governance/kill_switch.py:110` today only treats the literal string `"*"` as wildcard (per the docstring at L80) — so trailing-wildcard patterns like `ambient.*` would not match `ambient.budget-variance-watcher` until extended. **TASK-008b in this phase extends the matcher to support trailing-wildcard patterns** (formerly Phase 4 TASK-039 — moved here so SEC-002 holds the moment Phase 3 ships). After that landing, ambient-agent dispatch checks `is_killed(f"ambient.{agent.name}", tool="spawn_workflow")` before every spawn and `is_killed(f"ambient.{agent.name}", tool="reason")` before any LLM call.
- **SEC-003**: Ambient agents that invoke an LLM-backed `reasoning_skill` go through the **existing GHCP SDK + economics ledger** (the same path `FleetManagerService._process_batch` already uses). No new model-call path. The economics ledger already records cost; flag #4 from blueprint §12 is satisfied automatically.
- **SEC-004**: The `FUNCTIONS` registry is **read-only at runtime** (no mutation API; reload requires process restart, same as `DOMAINS`).
- **CON-001**: **No new agent runtime.** Ambient agents reuse the GHCP SDK + bus + simulator/durable client already in the substrate.
- **CON-002**: **No new orchestrator engine.** Spawning a workflow from an ambient agent calls the existing `simulator_orchestrator.spawn_workflow_by_type(workflow_type, payload)` shape (or the closest equivalent already in use); ambient agents do not start orchestrations directly via Durable's HTTP API.
- **CON-003**: **No `ChoreographyEngine`** (locked decision: dissolved in v2 of the blueprint).
- **CON-004**: **No `CadenceRunner` class.** `CadenceTrigger` is a *declaration* in Phase 3 — agents carrying one are registered in `AMBIENT_AGENTS` but their cron expression is **not evaluated** in this phase. The actual cron loop lands in Phase 4 (`AppState.cadence_loop`, <100 LoC, blueprint §2 Plane 4 + §9 Phase 4).
- **CON-005**: POC1 (`expense-claim`) and POC2 (`hiring`) stay legacy-tagged forever; **no payload migration, no entity projections, no per-function-FM coverage**.
- **CON-006**: FM context is **hybrid only** (locked decision #9): static identity templated from `FUNCTIONS` at session start; dynamic state via the five MCP tools. **No big precomputed dump** of in-flight workflows or KPI history into the skill text.
- **CON-007**: `query_kpi` returns an empty/stub structure in this phase — the `kpi_store` lands in Phase 4 (blueprint §9 Phase 4). The tool is wired and registered now so personae and FM prompts can call it, but the underlying store is `None` and the tool returns `{"metric": ..., "period": ..., "samples": [], "note": "kpi_store not yet provisioned (Phase 4)"}`.
- **GUD-001**: Each `FunctionFleetManager` is constructed by templating `api/server/skills/fleet-manager/SKILL.md` with the function's identity block (KPIs, owned domains, persona hierarchy, ambient watchers) — same trick `_domain_catalogue_section()` already uses in `api/server/services/fleet_manager_service.py` L37-L59.
- **GUD-002**: `AmbientAgent` instances are declared in `api/server/services/ambient_agents/<function>.py` and discovered at boot. Mirror the `DOMAINS` registry pattern: module-level immutable values, `__init__.py` aggregates into a single dict keyed by name.
- **GUD-003**: `CypherTrigger.sweep_seconds` defaults to `3600` (1h) and is per-agent. The dispatch loop creates one `asyncio.Task` per cypher-trigger.
- **GUD-004**: `BusTrigger.filter` is an optional Python expression evaluated by a tiny safe-eval that **reuses the `_DECISION_BUILTINS` whitelist pattern** from `api/server/services/persona_responder.py` L197-L205 (no new sandbox, no `eval`/`exec` outside it).
- **GUD-005**: `PersonaTree` lives on `FUNCTIONS` (locked decision #7): a small recursive dataclass `PersonaTree(role: str, manages: tuple["PersonaTree", ...] = ())`. Roles must resolve to a SKILL.md under `api/server/personae/<role>/`; boot-time validation enforces this.
- **PAT-001**: `Trigger` discriminated union via `dataclass(frozen=True)` with a `kind: Literal["bus","cypher","cadence"]` discriminator field. Consumers branch with `match trigger.kind` (mirrors how the rest of the codebase handles tagged-union shapes — see `Phase.kind` in `api/shared/domains.py`).
- **PAT-002**: Ambient-agent dispatch wiring in `AppState`: bus subscriber via `bus.on(event_type, handler)` for every `BusTrigger`, plus `asyncio.create_task(_cypher_sweep_loop(agent, trigger))` per `CypherTrigger`; the Phase 4 cadence loop will look up `CadenceTrigger`-bearing agents through a new `agents_by_trigger_kind("cadence")` helper exposed here.
- **PAT-003**: Per-function FM session creation **reuses the existing `FleetManagerService` shape**, instantiated per function rather than as a singleton. The constructor gains a `function: str | None = None` parameter; when set, the skill text and SSE topic are function-scoped. The fleet-wide singleton still passes `function=None`.
- **PAT-004**: `query_entity` and `find_entities` are **thin wrappers** around Phase 1's `EntityGraph` API (`graph.query(cypher, params) -> list[dict]` and `graph.query_one(...) -> dict | None` per Phase 1 plan). `query_recent_decisions` is a thin wrapper around the `Decision` node Cypher pattern Phase 1 already exercises in its `record_decision` helper.

## 3. Alternatives

- **ALT-001**: Make `Function` a stored entity in the Kuzu graph rather than a Python registry. Rejected: locked decision #2 puts source-of-truth in code (`FUNCTIONS` dict), mirroring the `DOMAINS` pattern that already drives the substrate. Compile-time validation, IDE refactor coverage, and import-time orphan checks beat a database schema for a list that changes on the order of one entry per quarter.
- **ALT-002**: Build per-function FMs as **subclasses** of `FleetManagerService` (`FinanceFM(FleetManagerService)`, `HrFM(FleetManagerService)` …). Rejected: the only per-function variation is *data* (skill text + tool-set + topic), not behaviour. A single `function: str | None` parameter (PAT-003) keeps the singleton path unchanged while the per-function instances reuse the same start/stop lifecycle.
- **ALT-003**: Add a `cron-runner` thread inside `AmbientDispatcher` to fire `CadenceTrigger`s in this phase. Rejected: blueprint §11 explicitly bans a `CadenceRunner` class; cadences land in Phase 4 as YAML files + one async loop in `AppState`. Phase 3 ships only the *declaration* — the dispatcher exposes `agents_by_trigger_kind("cadence")` so Phase 4 can hook in cleanly without touching Phase 3 code.
- **ALT-004**: Implement `find_entities` as a free-form Cypher pass-through with no audit trail. Rejected: SEC-001 + SEC-004 + the substrate's existing audit-everything posture (`AuditLogger.append` on every governance-relevant call) demand a `governance.find_entities` audit entry per call. The cost is one append per FM tool call — negligible.
- **ALT-005**: Compute the `Domain.function` back-ref on every read via `_DOMAIN_FUNCTION` lookup (no mutation of the frozen dataclass). Rejected: every existing call site reads `d.function` as an attribute (the spec quotes this in §2). A one-line mutation at import time keeps every consumer cheap; the discipline that the slot is mutated *exactly once* at boot mirrors the rest of the registry pattern.
- **ALT-006**: Spawn ambient-agent workflows by calling Durable's HTTP API directly. Rejected: CON-002. Reusing `simulator_orchestrator.spawn_workflow_by_type` (added in TASK-013) keeps every spawn going through one path that already integrates with the seed corpora, the per-domain ramp scheduling, and the audit ledger.

## 6. Risks & Assumptions

- **RISK-001**: Mutating the `function` slot on a `frozen=True` `Domain` dataclass requires either changing the dataclass to `frozen=False` (which loosens immutability of the other fields) or going through `dataclasses.replace` (which produces a new instance every consumer would need to switch to). Mitigation: TASK-002 picks the lower-churn path (drop `frozen=True`) and adds an explicit comment that `function` is the *only* slot mutated, exactly once, at import time. The validator in TASK-003 runs immediately after the mutation and would catch any later attempt to add a domain.
- **RISK-002**: Booting nine new long-running GHCP SDK sessions adds 9× the subprocess + token cost of the existing single fleet-wide FM. Mitigation: per-function FMs share the same `gh auth token` and run on the same GHCP SDK pool; the cost is a process + a session-state struct, not a separate token. If the dev-machine budget is hit, the lifespan loop can be gated by `FUNCTION_FMS_ENABLED=1` (TASK-043) so the autonomous-profile demo opts in while quick-start dev runs opt out.
- **RISK-003**: `_discover_ambient_agents()` walks the per-function modules at import time and any import-time exception there crashes boot. Mitigation: the discovery helper wraps each module import in a try/except that logs the failure and continues; the cross-validation against `FUNCTIONS[fn].ambient_agents` (TASK-008) loud-fails only on declarations that don't match — file-level syntax errors degrade gracefully to "no agents discovered for that function" with a loud log line.
- **RISK-004**: The `BusTrigger.filter` safe-eval (TASK-015) is a new attack surface. Mitigation: GUD-004 reuses the `_DECISION_BUILTINS` whitelist already battle-tested by personae for two phases of POC1/POC2 and the entire fleet-* substrate. No new builtins. The compile/eval pair is the same shape as `_compile_decision_policy` in `persona_responder.py` L208-L233.
- **RISK-005**: `query_kpi` returning a stub structure may be confusing to FM sessions that try to reason against it. Mitigation: the stub return includes an explicit `"note": "kpi_store not yet provisioned (Phase 4)"` field; the per-function FM skill text (TASK-026) calls this out so the LLM does not hallucinate KPI values.
- **RISK-006**: `CypherTrigger` sweeps with `sweep_seconds=86400` won't fire inside a 10-minute smoke test (TASK-044). Mitigation: the smoke test asserts on three concrete agents but the AccessAnomalyWatcher is a `BusTrigger` — it fires within seconds of an `it-access-request.completed` event, and the autonomous-profile already drives those at ~90s intervals. The two cypher-trigger agents have a `SIMULATOR_RAMP_AVG_INTERVAL_SECONDS`-style fast-path env var (`AMBIENT_SWEEP_SECONDS_OVERRIDE=30`) added to the dispatcher (TASK-014 supports an override) so the smoke test can force a 30s tempo for both.
- **ASSUMPTION-001**: Phase 1's `EntityGraph` API surface (`query`, `query_one`, `record_decision`, `find_by_pattern`) is stable as of the start of this phase and the `Decision`-node uniqueness on `(workflow_id, phase, persona_role)` is enforced.
- **ASSUMPTION-002**: Phase 2's `author-function-membership` sub-skill validates against the `FUNCTIONS` keys this phase introduces; if Phase 2 ships with hard-coded function names, those must match the ten keys in TASK-001.
- **ASSUMPTION-003**: The synthetic-journey domains listed in `api/shared/domains.py` (`fleet-*` × 11 + `creative-campaign` = 12) cover every non-legacy domain at the time of this phase. New domains added between Phase 2 and Phase 3 must update `FUNCTIONS[<owner>].owns_domains` in the same PR or the boot validator (TASK-003) will refuse to start the server — by design.
- **ASSUMPTION-004**: Operator UI is acceptable to continue showing fleet-wide FM activity on the existing `/fleet-manager` page; per-function activity lands on the new `/functions` page (TASK-041) without rewriting the existing one.
- **ASSUMPTION-005**: `gh auth token` is available in CI for the integration test (TASK-047); without it, the test is skipped (mirror of the existing FM startup test guard).
