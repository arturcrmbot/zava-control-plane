# Zava seller guide

**Purpose:** explain the operating pattern, show one inspectable decision and
make the next technical step understandable. No customer engagement is required
to prepare or rehearse this demonstration.

## Thirty-second introduction

> Most agent demos finish one task. Zava shows what has to be shared when work
> crosses an organisation: workflows, enterprise tools, authority and evidence.
> Follow a synthetic budget signal into an agent recommendation, an explicit
> CFO decision and real invoice-review workflows. Then inspect what happened.
> The operating records and external-system substitutes are synthetic; the
> reference code and execution boundaries are real. Existing investments connect
> at those boundaries rather than being replaced wholesale.

These are pacing targets, not execution-time guarantees. Let real work take the
time it needs. Do not replace missing evidence with a narrated outcome.

## Live and recorded use

Open the Constellation view and choose **Follow one decision**. It follows an
existing Aurora run or starts one when live has none. Advanced live demo controls
can explicitly start a new run. Retrying a failed start preserves its request
identity rather than silently creating another case.

The guide shows actual observed phases, the recommendation, policy decision and
child outcomes. In live mode, an authorised operator can approve or reject.
Recorded mode never offers writable approval controls. A historical tape with
no Aurora evidence says so; it does not manufacture a walkthrough.

For a technical session, use **Inspect workflow** and **Raw evidence**. Match the
root, child, decision and tool IDs. If a dependency fails, show that state
honestly and use the last approved recorded example rather than improvising.

## Questions to answer plainly

**Why not ordinary automation?** Use deterministic code for ordering, matching,
authority and side effects. The agent handles the bounded recommendation.
Zava demonstrates how those responsibilities coexist; it does not claim every
step benefits from a model.

**Is this a Microsoft product to buy?** No. It is a reference implementation
using Microsoft/cloud/developer components. Product support and licensing belong
to the selected services, not to an invented Zava product SLA.

**What is Microsoft's role?** The reference connects model execution, durable
work, workload identity and deployment on Azure with developer tooling. Explain
only the services used in the selected configuration. Do not add every portfolio
logo or claim unimplemented Agent 365/tenant integrations.

**What is synthetic?** Business records, external-system substitutes and
automatic personae. An automated exercise of the operator interface is not proof
that a real customer CFO approved something.

**Can existing agents and systems stay?** Yes, the reference has explicit
workflow, skill, tool and policy boundaries. Replacing a synthetic adapter is
integration work, not a promise of universal plug-and-play compatibility.

**How is it deployed?** Use the [reference installation guide](../zava-hosting-brief.md).
Private live and public replay are distinct modes. An assistant skill does not
substitute for resources, identity, permissions or release evidence.

**What does it cost?** Quote the actual region, fixed replica sizing, storage,
logging and selected model usage. Synthetic savings are not a customer ROI
calculation. Do not repeat an undated generic monthly estimate.

## Claims to avoid

- Every registered domain is fully implemented or every persona is a real person.
- A recorded or deterministic/fake-provider run proves live model quality.
- Infrastructure checkpoints guarantee full application recovery or exactly-once
  external actions.
- Governance-tool coverage is a security certification.
- A reference deployment is a production platform or a validated customer ROI.

## Before forwarding externally

Use a source-bound approved recording, consistent article/media and the actual
deployment instructions. Keep the real/synthetic boundary visible. Machine
checks do not supply human seller sign-off; working-tree proof footage remains
development material until the release gates are complete.
